Introduction

Learn what Hollow is and how it can help you build apps faster.

What is Hollow?

Hollow is a backend-as-a-service designed specifically for frontend developers. It gives you a working backend in minutes — without writing a single line of server code.

Why Hollow?

As a frontend developer, you shouldn't have to learn Express, set up a database, write authentication, or deploy to a server just to store some data.

Hollow handles all of that for you. Define your endpoints, configure your schema, and get a live API URL you can use immediately.

💡 Perfect for: Solo developers, indie hackers, frontend engineers, and anyone who wants to ship fast without building a backend.

Quick Start

Get your API running in 5 minutes with these 3 simple steps.

Step 1: Create a Project

Sign up and create a new project in the dashboard.

// POST /api/projects { "name": "My App", "description": "My first API" }

Step 2: Add an Endpoint

Define your endpoint and choose between Static or Dynamic mode.

// POST /api/projects/:id/endpoints { "method": "GET", "path": "/users", "mode": "dynamic", "schema": { "fields": { "name": { "type": "string", "required": true }, "email": { "type": "email", "required": true } } } }

Step 3: Use Your API

Your API URL is: https://hollow-3mbn.onrender.com/{projectId}/{path}

// Using cURL curl https://hollow-3mbn.onrender.com/proj_abc123/users // Using JavaScript fetch('https://hollow-3mbn.onrender.com/proj_abc123/users') .then(res => res.json()) .then(data => console.log(data));
🎉 Done! You now have a working API. Share the URL with your team or use it in your frontend app.

Authentication

Hollow uses JWT (JSON Web Tokens) for authentication. All dashboard API requests require a valid token.

Getting a Token

Sign up or log in to receive a token in the response.

// POST /api/auth/login { "email": "you@example.com", "password": "your-password" } // Response { "status": "success", "token": "eyJhbGciOiJIUzI1NiIs...", "user": { "id": "user_123", "email": "you@example.com", "name": "Your Name" } }

Using the Token

Include the token in the Authorization header for all dashboard API requests.

// Example with cURL curl https://hollow-3mbn.onrender.com/api/projects \ -H "Authorization: Bearer YOUR_TOKEN" // Example with JavaScript fetch('https://hollow-3mbn.onrender.com/api/projects', { headers: { 'Authorization': `Bearer ${token}` } })
🔒 Important: Keep your token secure. Never share it publicly or commit it to version control.

Creating Endpoints

Endpoints define the API routes your frontend will call. Each endpoint has a method, path, and mode.

Endpoint Structure

Field Type Description
method string HTTP method: GET, POST, PUT, PATCH, DELETE
path string URL path: /users or /users/:id
mode string static or dynamic
responses array Static mode only: list of response scenarios
schema object Dynamic mode only: field definitions

Static Mode

Static mode returns predefined responses. Great for mocking APIs, testing edge cases, and simulating different scenarios.

Response Configuration

Each static endpoint can have multiple response scenarios (success, error, unauthorized, etc.).

// Example static endpoint configuration { "method": "GET", "path": "/users", "mode": "static", "responses": [ { "scenario": "success", "isDefault": true, "statusCode": 200, "body": { "users": [ { "id": 1, "name": "Alice" } ] }, "delayMs": 0 }, { "scenario": "error", "statusCode": 500, "body": { "error": "Server error" }, "delayMs": 1000 } ] }
💡 Tip: Use the _scenario query parameter to test different responses: ?scenario=error

Dynamic Mode

Dynamic mode provides full CRUD operations with data persistence. Perfect for building real backends without writing server code.

How It Works

  • GET /users — Returns all users
  • POST /users — Creates a new user
  • GET /users/:id — Returns a specific user
  • PUT /users/:id — Updates a user
  • DELETE /users/:id — Deletes a user
// Example dynamic endpoint // POST /users POST https://hollow-3mbn.onrender.com/proj_abc/users { "name": "Bob", "email": "bob@example.com" } // Response { "_id": "67b1c2d3e4f5...", "name": "Bob", "email": "bob@example.com", "_createdAt": "2024-01-01T12:00:00Z", "_updatedAt": "2024-01-01T12:00:00Z" }

Schema Validation

Dynamic endpoints support schema validation to ensure data integrity.

Field Types

Type Description Example
string Text value "name": "Alice"
number Numeric value "age": 25
boolean True or false "active": true
email Valid email format "email": "alice@example.com"
url Valid URL format "website": "https://example.com"
// Example schema definition { "fields": { "name": { "type": "string", "required": true, "min": 2, "max": 100 }, "email": { "type": "email", "required": true }, "age": { "type": "number", "required": false, "min": 0, "max": 150 } } }

Public API

The public API is what your frontend applications use. No authentication required unless you enable API keys.

Base URL

https://hollow-3mbn.onrender.com/{projectId}

Endpoints

Method Path Description
GET /{path} List all items (dynamic) or static response
POST /{path} Create a new item (dynamic) or static response
GET /{path}/:id Get a single item (dynamic)
PUT /{path}/:id Update an item (dynamic)
DELETE /{path}/:id Delete an item (dynamic)
// Example public API calls GET https://hollow-3mbn.onrender.com/proj_abc/users POST https://hollow-3mbn.onrender.com/proj_abc/users GET https://hollow-3mbn.onrender.com/proj_abc/users/1 PUT https://hollow-3mbn.onrender.com/proj_abc/users/1 DELETE https://hollow-3mbn.onrender.com/proj_abc/users/1

Dashboard API

The dashboard API is used to manage projects and endpoints. All requests require authentication.

Projects

Method Path Description
POST /api/projects Create a project
GET /api/projects List projects
GET /api/projects/:id Get project details
PUT /api/projects/:id Update project
DELETE /api/projects/:id Delete project

Endpoints

Method Path Description
POST /api/projects/:pid/endpoints Create an endpoint
GET /api/projects/:pid/endpoints List endpoints
PUT /api/projects/:pid/endpoints/:eid Update endpoint
DELETE /api/projects/:pid/endpoints/:eid Delete endpoint

Data API

Manage stored data for dynamic endpoints.

Method Path Description
GET /api/projects/:pid/endpoints/:eid/data List all data
GET /api/projects/:pid/endpoints/:eid/data/:itemId Get single item
DELETE /api/projects/:pid/endpoints/:eid/data/:itemId Delete item

Using with React

Here's how to use Hollow in your React application.

// Create a simple API client const API_BASE = 'https://hollow-3mbn.onrender.com/proj_abc'; export const getUsers = async () => { const res = await fetch(`${API_BASE}/users`); return res.json(); }; export const createUser = async (data) => { const res = await fetch(`${API_BASE}/users`, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(data) }); return res.json(); }; // Use in a component function UsersList() { const [users, setUsers] = useState([]); useEffect(() => { getUsers().then(setUsers); }, []); return ( <div> {users.map(user => ( <p key={user._id}>{user.name}</p> ))} </div> ); }

Using with cURL

Test your API directly from the terminal using cURL.

# GET all users curl https://hollow-3mbn.onrender.com/proj_abc/users # GET a single user curl https://hollow-3mbn.onrender.com/proj_abc/users/1 # POST a new user curl -X POST https://hollow-3mbn.onrender.com/proj_abc/users \ -H "Content-Type: application/json" \ -d '{"name": "Alice", "email": "alice@example.com"}' # PUT update a user curl -X PUT https://hollow-3mbn.onrender.com/proj_abc/users/1 \ -H "Content-Type: application/json" \ -d '{"name": "Alice Updated"}' # DELETE a user curl -X DELETE https://hollow-3mbn.onrender.com/proj_abc/users/1

Error Handling

Hollow returns consistent error responses to help you debug issues.

Error Response Format

{ "status": "error", "message": "Email already registered" }

Common HTTP Status Codes

Code Description
200 Success
201 Created
204 No Content (successful delete)
400 Bad Request (validation error)
401 Unauthorized (invalid credentials)
404 Not Found (project or endpoint not found)
409 Conflict (duplicate email, etc.)
500 Internal Server Error
🔍 Debug Tip: Check the message field for details about what went wrong.
